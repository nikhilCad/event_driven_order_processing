# Step 0 — Architecture and setup

## Goal / Why
Design the whole system before writing code, and agree the working method. Central question: services each own their DB, so there is no global transaction — how do we stay consistent anyway? Every later step answers one slice of that.

## Architecture
See `PLAN.md` (Step 0) for the full diagram. Summary:
- 3 services (order, inventory, payment), each with its own database (database-per-service).
- Kafka (KRaft) in the middle; topics `orders.events`, `inventory.events`, `payment.events`, plus retry/DLT topics later. Key = `orderId`.
- Saga style: **choreography** (services react to each other's events; no coordinator).
- Order state machine: `PENDING → STOCK_RESERVED → CONFIRMED` | `→ CANCELLED`.
- Events: OrderCreated, StockReserved, StockReservationFailed, PaymentCompleted, PaymentFailed, StockReleased, OrderConfirmed, OrderCancelled.

## What we built
Only documents: `PLAN.md` (roadmap), `PROGRESS.md` (handoff + working agreement), `CLAUDE.md` (pointer for new agents).

## Decisions
| Decision | Choice |
|---|---|
| Build tool | Gradle (Kotlin DSL), multi-project, wrapper |
| Base package / groupId | `com.nikhil.orders` |
| Saga | Choreography (orchestration = Step 12 stretch) |
| Kafka | KRaft, no ZooKeeper |
| DB | One Postgres container, 3 databases |
| Outbox relay | Polling first, Debezium later |
| Tests | Testcontainers (real infra) |

## Q&A
**Why not Gradle? (I had proposed Maven)** — No strong reason; Maven was a default. Maven: declarative XML, most tutorials use it. Gradle: concise DSL, faster incremental builds, more flexible (but the build file is code). User chose Gradle; plan updated.

**Gradle version / isolation:** system `gradle` is 6.8.3 (too old for Spring Boot 4, needs 8.14+/9). We use the wrapper (Gradle 9.8.1). User did not want anything global touched, so the wrapper is configured with `distributionBase=PROJECT` and `zipStoreBase=PROJECT` → the binary lives in `.gradle/wrapper/dists/` (gitignored). Never touch `~/.gradle/wrapper/dists` (their other projects). `start.spring.io` returned HTTP 500 for Gradle projects, so the wrapper was generated by running a checksum-verified Gradle 9.8.1 download once.

**Base package:** `com.nikhil.orders`.
